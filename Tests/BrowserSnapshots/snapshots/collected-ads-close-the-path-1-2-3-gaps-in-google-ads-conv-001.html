      Summary

      Lands the three remaining gaps in the Data Manager / IngestEvents conversion-tracking plan. Everything is additive on top of the existing ECL upload path — no schema migration, no breaking API changes.

      • CallRail provider-link onboarding check. Guided/attested step (the Google Ads API doesn't expose [redacted-token] for read yet). New CallRailProviderLinkDialog mirrors GoogleAdsConsentDialog: 10s gate, deep-links to https://[redacted-token]?__c=<customerId>, and a one-shot I've done it posts to POST /api/workspaces/[id]/[redacted-token]. Status is derived in the existing GET /call-tracking so the modal only opens after the prior call-recording-consent step lands as linked — one modal at a time.
      • click_view enrichment of captured gclids. New findClickViewByGclid walks segments.date backward day-by-day (the API only accepts single-day filters, so a window lookup is N queries) and the gclidEnrichmentWorker Inngest fn stamps campaign / ad group / ad / keyword onto [redacted-token]. Triggered on agent/gclid.captured, dispatched on a fresh gclid stamp from the CallRail webhook and the new form endpoint. Idempotent on the gclid; misses still stamp lookedUpAt so we don't re-scan every retry.
      • Path 2 web-form gclid capture. New POST /api/webhooks/forms/[workspaceId]?token=<BESIDE_FORM_WEBHOOK_TOKEN> accepts { name, email, phone, gclid, gbraid, wbraid, sourcePage, occurredAt, externalId, fields }. Resolves contact via new resolveContactByEmailOrPhone unifier helper, stamps gclid metadata, dispatches a form_submitted interaction (now mapped to the qualified stage in the lifecycle map → existing ECL upload fanout takes it from there), and enqueues the click_view enricher.

      Also removes dead code surfaced during the review of competing tracking paths: the never-called CallRail listIntegrations / shapeIntegration / CallRailIntegrationShape surface plus its exploratory [redacted-token], and two stale lead-comments about deprecated Google Ads upload endpoints.

      What's NOT in this PR (deferred)

      • Per-lead EEA consent capture (still hardcoded CONSENT_GRANTED in the Data Manager payload). Acceptable while customers are US-only.
      • Auto-tagging on/off verification during onboarding (customer.auto_tagging_enabled is GAQL-readable; would add a 5-line check + a dialog).
      • Demoting Google's auto-created "Calls from ads" conversion to secondary when CallRail call assets land — flagged in review as the only competing-tracking issue that's a bug rather than a config warning.

      Test plan

      • pnpm dev + pnpm dev:inngest, sign in, confirm the new CallRailProviderLinkDialog opens only after the existing call-recording-consent flow shows linked, attest, confirm [redacted-token] is set and the dialog stays closed on reload.
      • Fire the CallRail webhook with a gclid against a workspace with Google Ads connected; confirm the new gclidEnrichmentWorker Inngest job runs and stamps [redacted-token] with campaign / ad group / keyword.
      • Curl the form endpoint with a name/email/phone/gclid payload and ?token=$BESIDE_FORM_WEBHOOK_TOKEN; confirm the contact is created/reconciled, gclid stamped, a form_submitted interaction lands, the contact moves to qualified, and the next ECL upload tick reports the conversion.
      • npx tsc --noEmit clean (was clean at commit time).
      • Vitest: pnpm exec vitest run [redacted-token] [redacted-token] (green at commit time).
